# 网络指标与加入前体检

2026-10-27 当前源码新增，尚未据此发布。目的只有一个：把「有的朋友会断」变成能动手的数字。

## 通话页逐人显示

每个人名字旁边有三格信号条；网络有波动或差的时候，名单那一行和篝火石头上会
多出几个字或一个角标，点开成员菜单能看到每一项的来源。规则在
[`client-runtime/src/call/network.rs`](../crates/client-runtime/src/call/network.rs)。

| 指标 | 谁量的 | 怎么来的 |
|---|---|---|
| 上行丢包 | **服务端** | 每个人的语音序号每包加一，静音不推进；服务端按序号缺口算最近 10 秒缺了几个。没人说话时退回保活统计（30 秒窗口，样本粗）。不依赖客户端配合，旧客户端也有 |
| RTT | 本人 | UDP 保活往返，在 Ping 里自报 |
| 收听丢包 | 本人 | 最近 10 秒收到别人语音的缺帧率，所有说话人合计，在 Ping 里自报 |
| 我收到他的丢包 | 本机 | 本机播放链路对那个说话人的接收估计，只对正在说话的人有 |
| 兼容连接 | 服务端 | 该会话当前走 TLS 语音路径 |

服务端每 3 秒把所有人的一份 `NetworkReport` 发给所有人（看门狗线程顺手做）。
协议版本仍是 2：`Ping` 多了几个可选字段，`ServerMessage` 多了一个分支，旧端都忽略。
旧服务端不发报告，这时客户端只有自己那一条，是拿 `Pong` 里的服务端收包数和自己的
发包数估出来的，成员菜单里标「本机估算」。

分级：丢包 ≥ 10% 或 RTT ≥ 300 ms 为「差」（一格红），丢包 ≥ 2% 或 RTT ≥ 150 ms
为「有波动」（两格黄），否则「好」（三格绿），什么都不知道就不画。
看别人取他的上行丢包和我收到他的丢包里较差的那个；看自己取上行和收听里较差的。

这些数字说明的是**线路**，不是对方的麦克风或声卡。上行丢包是服务端自己量的，
比任何自报都可信；RTT 和收听丢包是自报的，旧客户端不报。

## 加入前的网络体检

首页「网络体检」按钮：存过的服务器、输了地址的、刚加入失败的都能测。它走真实的
连接路径（TCP → TLS 固定指纹 → 认证 → 派生语音密钥 → UDP 保活），唯一区别是
`Hello.probe_only`：新服务端据此分配会话和密钥但**不把它放进名单**，频道里谁也
看不见；旧服务端不认这个字段，会把它当普通加入，体检期间根频道里会短暂出现一个
不出声的「网络体检」，报告里会写明。体检照常验邀请码和封禁；指纹没人担保时同样先
停下来让用户核对。

测什么：

1. TCP 连接耗时、TLS 握手耗时。
2. TLS 上 5 次 Ping/Pong 往返。
3. UDP **保活节奏**：每秒 10 包 × 5 秒，空负载。
4. UDP **说话节奏**：每秒 100 包 × 5 秒，每包 80 字节负载（约一帧 64 kbps 语音）。

两段各报发收数、丢包、RTT 最小/中位/p95/最大、抖动（相邻往返之差的平均绝对值）、
乱序数、最长连续丢包。结论规则在
[`client-core/src/netcheck.rs`](../crates/client-core/src/netcheck.rs) 的 `judge`：

| 结论 | 条件 |
|---|---|
| UDP 不通 | 两段一个回包都没有（TCP 是通的） |
| 像是按包速限流 | 说话节奏丢包 ≥ 8%，且比保活节奏高 5 个百分点以上 |
| 丢包严重 | 任一段丢包 ≥ 10% |
| 有波动 | 任一段丢包 ≥ 2% 或抖动 ≥ 30 ms |
| 延迟偏高 | 中位 RTT ≥ 200 ms |
| 良好 | 其余 |

报告是一段纯文本，不含加入码、身份和设备名，可以选中复制，也可以保存到
`%LOCALAPPDATA%\gouhuo\diagnostics\netcheck-<时间戳>.txt`。让断线的朋友在
**出问题的那个时段**测一次、把文字发给服主，几个人的报告放在一起对比最有用。

体检会话最多活 60 秒，服务端看门狗到点清理；它不占人数上限、不顶号、不消耗管理员链接。

## 它不能说明什么

- 十秒只代表这十秒。晚高峰的问题要在晚高峰测；有些 UDP 限流要持续几十秒才开始。
- 结论是提示，不是诊断书。报告里数字和结论分开写，服主可以自己判断。
- 上行丢包按序号缺口算：客户端重建语音链路、序号重置会被当作新起点，窗口里会有一两秒偏差。
- 服务端 `Pong` 里的收包数包含保活，旧服务端下的本地估算因此偏乐观几个千分点。

## 自动验证

- `protocol`：旧 `Ping` / 新字段互相解码，`NetworkReport` 的信封标签固定。
- `server`：序号缺口统计（窗口滚动、乱序、保活退路、长时间静默后重置）、报告快照、
  真 TLS 集成测试全部沿用。
- `client-core`：对真实服务端跑体检（不进名单、验邀请码、可取消）、服务端报告落到
  名单、服务端给过报告后本地估算不再覆盖。
- `client-runtime`：分级、文案来源、自报聚合。
