# 故障时间线与接收语音质量

2026-10-14，当前源码新增，尚未据此发布。真实 USB、蓝牙及休眠唤醒验收留待后续。

## 可事后导出的时间线

运行后自动在内存保留最近 5 分钟、最多 1800 条状态记录。无需提前开启；出现问题后
在通话页“…”→“诊断信息”→“导出记录”。状态轮询观测到变化时立即采样，稳定时每秒一次。
沿用前台 50 ms、后台 500 ms 轮询，可能略过比轮询间隔更短的中间阶段。
记录连接/运行阶段、会话与请求代次、设备就绪/变更代次、采集和播放进度、闭麦/
关闭声音/PTT 意愿、APM 状态、UDP/TLS 健康、各接收语音的质量及本地队列丢弃。
请求代次和运行阶段可用于追踪语音重建，传输状态可用于追踪回退和重连。

“暂停时间线”冻结已有现场；“继续时间线”沿用时间基准，不主动清空记录。
继续后超出 5 分钟的记录会自然过期。状态频繁变化时 1800 条上限可能缩短保留时长。
退出进程即清空未导出的内容；只在用户点击导出时写文件，不自动上传。
记录以 `started_unix_ms` 为时间基准，每行 `t_ms` 为单调时钟差值。
导出沿用可执行文件 SHA-256 和原诊断目录。

不记录音频、聊天、昵称、设备名称、地址、邀请码或密钥，不导出错误原文。
设备名称仅用于内存中的指纹比较，指纹也不导出，只记录变更代次；同名设备的
身份变化不一定能据此分辨，仍可通过重建请求与设备就绪变化定位。

## 最近 10 秒的接收估计

生产播放链路逐说话人记录数据，以 1 秒分桶形成约 10 秒的窗口；各人的序号和统计彼此独立。记录和窗口有上限，
过期后不把几分钟前的故障继续算进当前质量。保活、结束标记不计为语音接收包。

| 指标 | 含义 |
|---|---|
| 播放缺帧率 | 缺失序号占已播放与缺失帧总数的比例，接收估计 |
| 连续缺帧 | 最近窗口内最长连续确认缺帧；正常帧/结束/丢弃会重置连续计数 |
| 迟到、乱序 | 到达时已错过播放位置；或序号比最近已收到的较新包小 |
| PLC 比例 | 补偿帧占正常解码帧加补偿帧的比例；包括确认缺帧与等待 |
| 等待帧 | 下一个包及后续包都未到，尚不能确认丢包；独立计数 |
| 抖动峰值 | 相邻到达与发送间隔之差的绝对值峰值，不依赖两端时钟偏移 |
| 本地缓冲跨度 | 未解码序号跨度与已解码 FIFO 的时长，不是嘴到耳延迟 |
| 溢出/过旧帧丢弃 | 接收缓冲容量丢弃与积压上限主动丢弃，独立于网络缺帧 |

正常结束和静音不制造缺帧。末尾断流、丢失结束标记、发送端漏发或设备故障可能
影响接收估计，不能用它确认网络根因或端到端丢包率。尚无接收反馈送回发送端。
PLC 不等同于 FEC；本次不修改码率或增加 FEC 路径。

少于 20 个已播放/确认缺失帧时标为样本不足。启发式规则：缺帧至少 10%、PLC 至少
15%、连续缺帧至少 5 帧、本地丢弃或缓冲至少 250 ms 时为明显异常；缺帧至少 2%、
PLC 至少 3%、迟到至少 2 帧、抖动峰值至少 30 ms 或缓冲至少 150 ms 时为波动。
这些规则是诊断提示，不是主观音质评分或公网 SLA。窗口恢复后提示清除。

通话页显示受影响接收语音路数，诊断展开各会话的数字。质量与连通性分开：
保活正常也能提示质量波动；这些指标不触发重连、音频重建或 UDP→TLS 切换。
接收指标不能证明自己的上行送达，原有双向保活和单向中断检测保持独立。

## 防止恢复后继续播放积压语音

故障注入发现：早期大批包集中到达后，旧的加速播放路径可能在 15 秒后仍积压
约 700 ms。自适应播放现在每拍将未解码序号跨度限制为 300 ms，丢弃过旧帧并记录
`stale_dropped`；固定缓冲测量路径保持原规则。已解码 FIFO、设备及网络延迟不包含
在该上限内。它会牺牲部分过旧语音来及时恢复，不能承诺丢包期间一句不漏。
