# 篝火 0.2.1：发布说明

状态：准备发布。跟 0.2.0 **协议兼容、存档兼容**：`PROTOCOL_VERSION`、SQLite 表结构、
邀请链接格式都没动，客户端和服务端可以分开升级。从 0.1.x 升上来的仍按
[0.2.0 升级与验收](release-0.2.0.md) 走。

## 这一版有什么

### 不用再传长链接：输域名或 IP 就能加入（#37）

客户端没连服务器时是一个新首页：上面是上次去的服务器和「回到篝火」，右边是像素篝火，
下面是其他存着的服务器和「加入新服务器」，底部是昵称和试麦。

「加入」的那个框认四样东西：

| 输入 | 怎么确认是这台服务器 |
|---|---|
| `gouhuo://j/…` 邀请链接 | 证书指纹就在链接里 |
| `https://voice.example.com/` 加入页地址（可带 `#code=…`） | 加入页给出指纹，域名的 HTTPS 证书担保 |
| `voice.example.com` 域名 | 先找它的加入页；没有就按下一行处理 |
| `203.0.113.7`、`host:20800` | 客户端取回指纹，用户跟服主核对后才连，之后记住 |

- 核对指纹之前不发身份、昵称和加入码。
- 私人服务器在服务端要加入码时才问；加入码不在加入页上，也不在任何公开的地方。
- 加入成功的服务器存在 `%APPDATA%\gouhuo\settings.txt` 里（`server.N.*`，私人服务器的
  加入码也在里面）。老版本只记一条的 `last_invite` 会自动变成第一个。
- 服务器换了证书时报错并给「重新验证服务器」。

### 服务端：可选的浏览器加入页（#37）

域名上可以架一个 HTTPS 加入页：浏览器打开后点按钮唤起客户端，没装客户端时给下载和
复制邀请链接的退路。旁边还有一份给客户端读的说明（`/.well-known/gouhuo`），上面
「输域名加入」靠的就是它。两者都不含加入码。

**默认不启用。** 不设 `GOUHUO_WEB_LISTEN` 就不多一个线程、一个端口。启用方式、代价和
不编进去的办法见 README「用域名打开 HTTPS 加入页」。

### 音质（#35 / #36）

- 混音在大音量处的突变（0.7 附近输出跳变）改成了连续的软限幅。
- AGC2 打开自适应数字增益（最大 20 dB），用来把偏小的声音拉起来。在合成信号上验证过，
  真人轻声还没验收。
- 默认 Opus 码率 24 → 32 kbps。

细节和可复现的对比工具见 [音质修复与验收](audio-quality.md)。真人盲听还没做。

## 行为变化

- **普通启动停在首页，不再自动连上次的服务器。** 回车或点「回到篝火」进去。
  点邀请链接启动的老用户仍然直接连。
- 默认码率提高后，每个说话的人上行多约 8 kbps。
- 证书对不上的报错里不再带 `unexpected error:` 这种前缀；频道界面左上角显示服务器名
  （加入页给的名字，没有就是地址）。

## 升级

- **客户端**：装 0.2.1 安装包覆盖即可。设置文件里会多出 `server.N.*` 几行；换回 0.2.0
  也读得了（它不认识的行会跳过，`last_invite` 还留着）。
- **服务端**：`docker compose pull && docker compose up -d`。在线的人会断一下再自动重连。
  数据卷不用动，证书指纹和已发出的邀请链接不变。
- **想开加入页**（可选）：
  - 机器上 80/443 空着：用 `compose.https.yaml`（带 Caddy），或者 `install.sh` 的 `GOUHUO_HTTPS=1`。
  - 已经有 nginx 之类的反向代理：在 `.env` 里设 `GOUHUO_WEB_LISTEN=127.0.0.1:20801` 和
    `GOUHUO_JOIN_URL=https://你的域名/`，代理把这个域名转到 `127.0.0.1:20801`。
    README 里有 nginx 的例子。
  - 语音的 20800（TCP/UDP）照旧直连，不经过代理。

## 验证

自动（2026-09-30，Windows 本地，CI 同样的四项门禁）：

- `cargo test --workspace`：497 项通过，0 失败，12 项按既有设置跳过。
- `cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、
  服务端 `--no-default-features` 的 clippy、`scripts/check-spdx.py`（91 个文件）通过。
- 服务端带和不带加入页两种 Docker 镜像都实际编过、跑过。

真实环境（2026-09-30）：一台公网 Linux 服务器，真实域名，Docker 版 nginx 反代加入页，
Let's Encrypt 证书；客户端是 release 构建、全新身份。

- 输裸域名：从加入页取到地址和指纹，不用核对指纹，问加入码，加入成功，语音连通。
- 粘带 `#code=` 的浏览器邀请：直接加入；存下的加入页地址里不含加入码。
- 加入页不可用（502）时输裸域名：退回直连，出现核对指纹，指纹与服务端日志一致。
- 加入页不可用时输 `https://` 地址：明确报「没有加入页」，不卡住。
- release 构建拒绝 `http://` 的加入页。
- 浏览器打开加入页：桌面宽度显示正常，无脚本报错。

本机（debug 构建，本地服务端）还走过：输 IP 核对指纹加入、错加入码、首页快捷进入、
运行中和冷启动点邀请链接、取消、连不上、证书变了重新验证、移除服务器、窄窗口和最小窗口。

- `compose.https.yaml`（Caddy）和 `install.sh` 的 `GOUHUO_HTTPS=1`：没在真机上跑过。
  真实环境验证走的是「已有反向代理」那条路。
