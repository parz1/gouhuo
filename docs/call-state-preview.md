## 三种不同含义

1. **输入电平**：APM 处理后的麦克风输入，不是原始采样，也不是服务器送达确认。
2. **发送模式**：VAD 按人声触发；PTT 按绑定按键触发。模式不等于正在发送。
3. **发送状态**：取实际发送门控结果，结合当前链路可用性表达；仅表明本地语音发送，
   不宣称每个听众已经收到或听见。

闭麦不停止采集，电平仍可变化；灰色输入条不能被误读成发送响应。设备失效或
重连后，冻结的旧电平必须清空或标为不可用，不能继续当成实时输入。

## 状态矩阵

| 条件 | 输入显示 | 底栏文案 | 自身场景响应与操作 |
|---|---|---|---|
| 只有自己 | 按实际输入 | 模式与发送状态独立显示；频道人数为 1 | 自己一座，其他空座；不把「没有队友」误写为没有连上 |
| 多人（12 人示例） | 按实际输入 | 频道 12 人 | 圈内八座，另有四人入口；完整成员列表可滚动；额外成员说话时入口同时有图标/文字 |
| 长昵称 | 按实际输入 | 名单与石座可截断 | 成员菜单显示全名；操作以成员标识关联，不能因同名或截断混淆 |
| VAD 无输入 | 中性空条与阈值刻线 | 语音激活 / 等待人声 · 未发送 | 自身无说话高亮 |
| VAD 有输入，未过阈值且尾音门控已结束 | 中性条低于刻线 | 语音激活 / 未发送 | 输入可见，自身无说话高亮 |
| VAD 过阈值 | 实时输入与刻线 | 语音激活 / 正在发送 | 自身说话高亮，并有麦克风图标/文字 |
| VAD 尾音保留 | 电平可能已低于刻线 | 语音激活 / 正在发送 | 发送门控结束后才停止高亮；评审图「尾音保留」标签解释此边界，产品不必常驻技术术语 |
| PTT 未按下 | 中性实时输入，无 VAD 刻线 | 按住 V 说话 / 等待按键 · 未发送 | 自身无说话高亮；V 使用真实绑定键名 |
| PTT 按下，未闭麦且链路可用 | 实时输入，无刻线 | 按住 V 说话 / 正在发送 | 自身高亮；即使输入很低也不根据电平另作 VAD 判定 |
| PTT 未绑键 | 中性实时输入，无刻线 | 按住说话 / 未绑定按键 · 未发送 | 小型「绑定」入口；仍有闭麦、关闭声音与设置 |
| 已闭麦 | 中性实时输入可变化 | 已闭麦 / 未发送 | 无自身高亮；红色划线状态图标，按钮动作为「开麦」 |
| 已关闭声音 | 中性实时输入可变化 | 已关闭声音 / 已闭麦 · 未发送 | 无自身高亮；「打开声音」，开麦禁用并说明先打开声音 |
| 重新打开声音 | 中性实时输入 | 已闭麦 / 未发送 | 保留闭麦，需另点开麦，避免突然发送 |
| TCP 重连 | 不可用，不显示旧电平 | 正在重连 / 语音暂停 · 未发送 | 名单标为暂未更新，清除所有历史说话高亮；「取消并离开」沿用离开回调 |
| TCP 恢复，UDP 待验证 | 按新采集链路可用性 | 正在验证语音 / 未发送 | 沿用原频道、自身设置和音量；验证成功前不显示恢复成功 |
| 输入设备故障 | 不可用 | 麦克风不可用 / 未发送 | 提示受影响设备；自动恢复、重试语音、选择设备、诊断 |
| 输出设备故障 | 若采集仍在工作则仍显示实时电平 | 播放设备不可用；当前错误/恢复期不显示正在发送 | 不写「麦克风没有输入」；提示换输出设备。当前统一 error 会压住发送展示，后续按实际链路状态核对 |
| UDP 未连通 | 若采集可用可有中性实时输入 | 语音网络未连通 / 未发送 | 自动恢复、重试语音、诊断；文字入口保留，不宣称支持 TCP 语音回退 |

所有绿色发送标记仅用于「正在发送」；模式标签、等待状态与未发送采用中性色。
一般「闭麦」动作使用中性未划线图标；已经闭麦时红色状态图标与「开麦」动作分开。
异常不隐藏闭麦意愿，恢复沿用用户状态，不能因自动恢复擅自开麦。

## 程序语义核查与实现（已撤回版本）

以下描述针对撤回实现。当前回滚代码仍由 UI 猜测发送状态，VoiceStats 没有下述新增字段；重建计划见新方案。

- 输入电平来自 APM 处理后的采集帧。闭麦只阻止发送，不停止采集；输入可用性单独由采集线程上报，采集退出和重连清除可用性。
- `VoiceStats.transmitting` 来自编码、加密和发送成功的结果，保留 VAD 的 200ms 尾音门控；闭麦、PTT 松开和停止链路会立即屏蔽旧状态。
- 删除 UI 按电平猜测发送的 `transmitting_now`，PTT 轮询只控制发送门控；UI 统一结合闭麦、关闭声音、UDP 和恢复状态显示。
- 关闭声音同时闭麦，关闭期间不能开麦；重新打开声音保留闭麦。服务端回报的自身状态同步回本地语音管线。
- 输出故障不被误写为没有采集；输入条按实际采集可用性显示，错误/恢复期暂停发送展示。恢复策略沿用 [connection-recovery.md](connection-recovery.md)。

对应源码：`crates/voice-core/src/pipeline.rs`（VoiceStats、TransmitGate、send_loop、stats）与
`crates/client/src/main.rs`（spawn_ptt_poll、语音轮询、toggle_deafen、refresh、Event::Reconnecting）。

## 正常与窄窗口的主要路径

| 任务 | 正常窗口 | 窄窗口 |
|---|---|---|
| 切频道 | 左侧选择目标频道，主标题跟随服务端结果 | 频道 → 选择频道 → 返回通话；选中的是当前实际频道，不预先宣称切换成功 |
| 调成员音量/本地静音 | 成员行或石座 → 同一菜单 | 频道名单或石座 → 同一菜单；超出八座从「还有 N 人」进入 |
| 管理成员 | 同一菜单中显示有权限的管理操作 | 同一菜单；无权限不展示；权限仍由服务端决定 |
| 闭麦/开麦 | 全宽底栏 | 底栏第二行，导航、文字、诊断打开时位置不变 |
| 关闭/打开声音 | 全宽底栏 | 同上；关闭声音时开麦入口说明受限原因 |
| PTT 绑键 | 底栏未绑提示 → 绑定；使用现有按键绑定流程 | 同上；绑定提示可折行，开关不被挤走 |
| VAD/PTT 选择 | 底栏模式入口打开轻量选择，调整细项进入现有设置 | 模式文字也有明确可点击入口；不把更改模式藏在场景里 |
| 文字 | 顶部文字切换 | 顶部文字切换；底栏留在外层，输入区与消息内容滚动 |
| 恢复异常 | 标题下提示 → 重试语音 / 设备 / 诊断 | 提示最多优先放一个主要动作，设备与诊断为次级；内容可滚动，底栏不滚动 |
| 取消重连 | 异常提示的取消并离开 | 同上；不能用关闭提示替代取消连接 |
| 设置/离开 | 底栏设置；顶部离开 | 同位置；返回通话、关闭菜单、关闭诊断均不触发离开 |

导航分界为 640px，底栏自行在 736px 切换两行；导航打开时只替换中间内容，不另外覆盖底栏。
已实现正常侧栏 208px；宽标题 56px、窄标题 80px；底栏宽版 65px、窄版 105px，最小 400 × 360。
宽版底栏上下留白均为 12px，窄版均为 8px；麦克风输入和语音模式共用 24px 标题行与 16px 状态行，输入电平条从左侧增长，模式箭头位于标题右侧。
上述窗口尺寸已通过软件渲染检查，Windows 缩放仍需原生窗口验收。
标题、异常提示和底栏先取得空间；场景用剩余高度，极矮时可隐藏装饰，只保留成员入口。
恢复详情可滚动，不能挤出闭麦/声音开关。

## 键盘与焦点行为

普通窗口的区域顺序：频道导航 → 顶部文字/离开 → 可见异常动作 → 场景成员入口 →
底栏闭麦/声音 → 模式或绑定入口 → 设置。窄窗口先从频道按钮开始，后续相同。
Shift+Tab 反向；仅实际可操作元素进入 Tab 顺序，昵称、输入电平和状态文字不单独抢焦点。

- 频道和成员列表各作为一个列表焦点组，用上下键浏览，Enter 执行选中项，
  不要求对每个人逐次 Tab；到无权限项不提供虚假可执行动作。
- 频道导航打开后，焦点进入当前频道；关闭时回到稳定的底栏操作入口。
  Esc 先关闭最上层菜单或导航，不等价于离开频道。
- 成员菜单内按「音量 → 本地静音 → 有权限的管理项 → 关闭」排列，滑条方向键调整。
  关闭后回到触发的成员行/石座；成员离开则回到成员列表入口。
- 导航与场景入口可以指向同一成员，但每个入口清楚读出昵称与状态。
  场景在隐藏、菜单弹出或文字视图时，其不可见入口不进入焦点序列。
- 新出现的异常不抢当前焦点；通过状态公告说明，恢复动作随后可达。
  当前有焦点的动作因恢复消失时，焦点回到稳定的底栏闭麦入口。
- 全局 PTT 是既有绑定键；不新增默认抢占游戏按键的全局快捷键。
  绑定过程的 Esc 和普通导航的 Esc 按现有绑定取消规则分别处理。
