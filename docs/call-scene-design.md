## 固定操作区

| 区域 | 宿主负责的内容 | 窄窗口位置 |
|---|---|---|
| 频道与成员导航 | 服务器、频道树、当前频道、完整成员列表与成员操作入口 | 顶部「频道」打开导航；「返回通话」关闭导航 |
| 通话标题 | 当前服务器与频道、人数、文字切换、离开 | 顶部，可分两行 |
| 异常提示 | 重连、设备故障、UDP 未连通，及现有恢复与诊断入口 | 标题下方，独立于场景显示 |
| 自身状态与操作 | 昵称、输入电平、说话模式、发送状态、闭麦、关闭声音、设置 | 底部两行常驻，导航打开时仍保留 |
| 成员操作菜单 | 完整昵称、个人音量、本地静音及有权限的管理操作 | 宿主统一展示；场景点击成员也进入同一菜单 |

场景不改变这些区域的位置、操作含义或状态真实性。焦点留在宿主可管理的
导航、按钮及成员入口上；场景提供成员入口时，应能用键盘到达并读出昵称与状态。
长昵称完整内容在成员菜单中可见，截断显示不影响操作对象的身份。

## 社区场景区

可替换范围是标题与底栏之间的主画面：背景、成员的视觉形象与位置、说话响应、
加入与离开动画。官方「像素篝火」以围火石座表示成员；其他方案可以使用
太空舱、酒馆等场景，而无需重新设计整套通话操作。

现有官方场景的八个座位和超出座位后的成员入口是当前实现规则，不是所有社区
场景必须遵循的限制。任何场景都应覆盖无人陪伴、多人、人数超出画面容量与
长昵称；完整成员导航作为始终可用的操作入口。

## 宿主与场景的数据、交互边界

以下是设计契约，具体格式与实现接口另行确定。

- 宿主提供最少的展示状态：成员标识、昵称、是否为自己、闭麦、关闭声音、
  正在说话，以及当前频道、窗口尺寸与动效偏好。
- 自己是否正在发送由宿主计算，场景仅用于呈现；不通过动画、电平或麦克风图标推断。
- 场景点击成员时返回成员标识，由宿主打开统一操作菜单；音量、静音、管理权限
  与实际操作由宿主处理，场景不自行执行。
- 音频设备、采集与播放、连接恢复、协议、身份和密钥都属于宿主。
  第一阶段场景包不需要原始音频、密钥、任意网络访问或可执行代码。
- 场景切换不应退出频道或重建语音链路。加载失败、格式不兼容或资源超出限制时，
  回退到官方场景，并保留宿主操作和状态。

## 状态表达

输入电平表示「麦克风有输入」；VAD/PTT 表示「怎样允许发送」；「正在发送」
是另外一个状态。三者在底栏分别表达，场景不得把输入电平直接当成发声高亮。
本地发送状态不能宣称对方已收到或听见。

| 状态 | 底栏表达与场景响应 |
|---|---|
| VAD 未触发 | 语音激活、未发送；输入可有电平，自身无说话高亮 |
| VAD 或 PTT 正在发送 | 模式与正在发送文字；自身出现说话响应 |
| PTT 等待按键 | 按住指定键说话、等待按键、未发送 |
| PTT 未绑键 | 未绑定说话键、未发送，提供绑定入口 |
| 闭麦 | 已闭麦、未发送，按钮动作是「开麦」 |
| 关闭声音 | 已关闭声音、已闭麦、未发送；按钮动作是「打开声音」，恢复声音后仍需单独开麦 |
| 重连 | 正在重连、语音暂停，保留现有取消/恢复流程，不显示自身发送响应 |
| 设备故障 | 说明受影响的是输入还是输出，提供适用的重试/设备入口；不将播放故障误写为采集故障 |
| UDP 未连通 | 语音网络未连通、正在恢复，恢复与诊断为宿主入口；不显示自身正在发送 |

状态同时使用文字或图标，不仅依赖颜色。源码核查确认闭麦仍可有输入电平，
撤回版本曾将发送事实与输入电平分开，覆盖闭麦、VAD 尾音、链路和恢复状态；当前代码已回滚，待按新方案重建。
详见 [程序语义核查](call-state-preview.md)。

## 场景包的分阶段方向

第一阶段优先探索声明式「场景包」：元信息、图片/动画资源、成员位置与响应规则，
由宿主控制渲染和交互。包版本、资源体积、解码尺寸、动画频率、人数容量、
兼容性与回退规则在接口设计时确定，不在草图阶段预设未经测量的数值。

任意代码插件、社区分发平台、上传与安装流程均留待单独设计。先验证官方场景
能通过同一契约运行，再决定是否需要更复杂的扩展能力。保留现有小体积、低资源
占用目标；隐藏、最小化或游戏全屏时的动效节流由宿主统一管理。
