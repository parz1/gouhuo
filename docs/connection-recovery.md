# 语音中断检测与恢复

客户端连接包含 TCP 控制面与 UDP 语音面。TCP 在线、还能收到别人语音，都不能单独证明自己的语音能送达。

## 本次修复

- 托盘或最小化时每 500 ms 检查语音健康，前台仍为 50 ms。
- UDP 每 2 秒保活，8 秒没有有效回复后提示语音中断。保活失败不会因为仍在收到别人的语音而被掩盖。
- 每次中断只播放一次三音下降提示；自动重试不会反复响。实际 UDP 保活恢复且音频没有报错后播放一次三音上升提示。
- 声音遵循已有提示音开关、音量与关闭声音设置；播放设备本身故障时无法保证声音可听见。
- 只有 UDP 保活超时时，保留音频设备和原 UDP socket 继续探测，不通过反复开关麦克风、扬声器尝试修复网络。持续失败再升级为整个会话重连；完整重连至少间隔 30 秒，短暂恢复不会清掉冷却时间。音频设备故障仍重建音频链路，不重连服务器；准备失败或网络线程错误仍沿用语音重建路径。
- 桌面客户端与 talker 使用已认证 TCP 连接实际到达的 IP 和 Welcome 的 UDP 端口，并与同一连接的会话、密钥一起取快照。避免域名重新解析后把 UDP 发到不可达 IPv6 或另一台服务器。
- 音频重试间隔按 2、4、8、16、30 秒增加；新 UDP 链路在探测期间不重复重建。
- TCP 重连成功后显示“正在验证语音”，语音恢复前不播成功提示。原频道、闭麦、关闭声音与个人音量沿用原有恢复逻辑。
- TCP 断开时停止旧语音链路的采集和网络线程，保留本地播放用于断线提示。最终被拒绝时最多保留 400 ms 播放时间；主动离开不播放故障提示。
- 关闭 TCP 不再等待 TLS 写锁，写入失败触发断开，写超时为 8 秒。
- 诊断快照增加服务端最近报告的 UDP 接收数和本次加入最近 20 条恢复记录；记录只保存在内存，不包含邀请码、密钥或聊天内容。

没有改变协议或服务端，现有香港服务器可以配合新客户端使用。UDP 保活确认的是客户端与服务器之间的双向通路，不是每个听众的实际收听确认；服务端 UDP 接收计数包含保活，不能当作语音送达确认。

## 自动验证

- 真 UDP 代理分别切断上行与下行，TCP 保持在线。上行切断时下行语音包仍持续到达，但 UDP 健康检查仍判定异常；线路恢复后状态恢复。
- 真 TLS 服务端验证主动重连后换会话和密钥，恢复原频道、闭麦与关闭声音；主动退出后不再重连。
- 音频采集结束和采集报错能够显式报告，即使 UDP 保活正常。
- 停止采集及网络后仍能通过原播放混音输出本地断线提示。
- 用可控时间验证重试退避、通知去重、完整重连限频、设备故障不触发 TCP 重连。
- 持有 TLS 写锁时，取消连接无需等待写锁。
- 域名 localhost 连接仅监听 IPv4 的真实 TLS 服务端，语音地址绑定 TCP 实际对端，并收到可解密的 UDP 保活回复；重连后的地址、会话和密钥来自同一连接。
- 可控时间覆盖纯 UDP 超时不重开音频、持续失败升级重连、短暂恢复后再次失败仍保持冷却；网络接收线程错误与真实设备错误仍重试语音。
- 诊断增加当前语音目标 IP / 端口；恢复记录在重建前保存 UDP 超时标志、准备 / 采集 / 播放 / 网络错误，避免重建后现场错误消失。

## 0.3.0 用户反馈后的修复边界

2026-10-03 收到不断重连、游戏声音时有时无的反馈，设备可能为虚拟声卡，尚无现场诊断或可复现步骤。上述地址与恢复策略修改针对源码中确认的隐患，不代表已经确认该反馈根因。WASAPI 仍使用共享模式，未修改驱动等待超时，也未验证具体虚拟声卡的游戏音频路由。需用修复后的客户端和用户原设备继续验收。
