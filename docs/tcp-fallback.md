# TLS 语音回退与诊断记录

当前源码实现，已迁入 0.3.3 主线架构，但尚未发布。桌面客户端、服务端与测试机器人共用该通路；独立 UDP 探针和旧的 talker 示例保持原来的 UDP 行为。

## 使用与兼容

正常使用无需设置。客户端优先使用 UDP；连续约 8 秒没有有效双向保活回复时，请求通过已有的 TLS 控制连接传输语音。请求由服务端确认后生效，页面显示“兼容连接 · 延迟可能增加”。语音设备、编码器、会话密钥和发送序号不因路径切换重建。

回退期间每 2 秒继续探测 UDP。连续三次收到当前探测的认证回复后请求切回；重复、旧序号和其他会话的回复不计入恢复。TLS 语音保活使用独立的新序号，经 TLS 往返验证；TCP 控制心跳在线本身不算语音恢复。TLS 收包不会增加 UDP 健康计数，也不会修改服务端学到的 UDP 地址。

协议仍为版本 2。`Welcome.tcp_voice` 是新增的可选能力字段；旧服务端未声明能力时，新客户端沿用 UDP 和原恢复策略。旧客户端不会请求新路径，新服务端继续按 UDP 转发。新路径需要客户端和服务端都升级，协议版本和存档格式不变。

TLS 和 UDP 成员可在同一频道互听。转发继续使用现有频道规则、逐连接密钥和共享防重放窗口；TLS 上声称的发送会话必须等于已认证连接的会话。重连后的新会话不接受旧连接的语音句柄。

## 独立语音进程

2026-10-22 迁移后，UDP、Opus、音频设备、序号分配与语音健康探测仍在声音内核；
客户端进程保留认证后的 TLS 控制连接。IPC v2 只中继已加密的数据报、路径确认与撤销状态，
每批最多 32 个包；两端仍使用有界、100 ms 过期队列，跨进程保留过期截止时间。
客户端优先写生命周期/控制命令，轮询不重复应用闭麦/PTT；旧进程、旧请求或旧控制版本的回包会被丢弃。
闭麦、PTT 松开与会话回收会立即撤销客户端 TLS 待发队列。路径切换不重启声音内核；
设备替换沿用会话序号与已确认路径。IPC 批处理会增加一定调度等待，未据此重新宣称公网延迟。

客户端需与本次源码的 0.1.2 声音内核配套构建。IPC v1 的 0.1.1 内核不兼容 IPC v2，
声音内核更新清单也需匹配 IPC 版本；本次没有发布应用或内核。

## 队列与延迟边界

- 两端保留独立的控制消息队列，写线程先处理控制消息，再取语音；音频线程不等待 TLS 锁或网络写入。
- 语音队列最多 128 个数据报，每包不超过现有 `MAX_DATAGRAM`；满时丢最旧包，排队满 100 毫秒即过期。
- 写锁等待后再次检查语音是否过期或已撤销。闭麦、PTT 松开、停用发送、退出和路径变更会撤销相应待发语音，已交给操作系统的字节无法撤回。
- 客户端接收侧在更新播放与说话状态之前去重；服务端两条入站路径共用防重放窗口。
- 控制优先只适用于尚未写入 TLS/TCP 的消息。已经在 TCP 字节流中的数据仍受重传和队头阻塞影响，回退不保证比 UDP 更低延迟，不因少量丢包切换。
- TCP 端口仍需可达。HTTP 反向代理不能直接代理此原生 TLS 协议；平台适配需单独验证。

## 诊断记录

通话页右上角“…” → “诊断信息” → “导出记录”。当前源码自动保留短期故障时间线，无需提前开启；可点击“暂停时间线”冻结现场。导出状态显示文件位置：

`%LOCALAPPDATA%\gouhuo\diagnostics\diagnostics-<时间戳>.txt`

记录默认启用，保留最近 5 分钟、最多 1800 条内存记录：轮询观测到状态变化立即采样，稳定时每秒一次。暂停后仍可导出；继续沿用时间基准，旧记录按时间窗口自然过期。退出进程后未导出的记录会消失。不是崩溃转储或永久后台日志。接收语音质量指标、窗口边界和故障注入验证见 [故障时间线与接收语音质量](weak-network.md)。

记录包含版本、协议、系统、请求/会话代次、运行阶段、设备是否就绪/虚拟输入、错误类别标志、闭麦/PTT 意愿、UDP/TLS 健康、收发计数、播放欠载及本地隧道队列丢包。错误保留类别而不导出可能含设备名或地址的原始错误字符串。导出后台计算可执行文件 SHA-256，区分版本号相同的本地构建。

不记录音频、聊天、昵称、设备名称、地址、邀请码或密钥。原有诊断快照仍可在窗口查看，导出按钮仅导出上述受限记录，不打包身份或设置文件。服务器侧队列丢包不包含在客户端本地丢包计数中。
